What is different about fab data

Volume is the obvious difference, but it is not the hard part. The hard part is that volume keeps growing while the questions stay urgent. A query that ran in seconds on one fab's telemetry takes minutes once the data from several fabs lands in the same tables, and a pipeline that was cheap last year becomes the biggest line in the cloud bill this year.

Manufacturing data also crosses boundaries that other industries keep apart. One analysis might join tool telemetry, yield, test results, and finance data from an ERP system, each owned by a different team with its own idea of what a lot or a wafer means.

Where I help

  • Pipelines that stay predictable. Spark partitioning and tuning so query performance and pipeline cost stay predictable as volumes grow, instead of being rediscovered every quarter.
  • Data models over telemetry. Models over high-volume manufacturing and sensor data that analysts and engineers can query without knowing how it was partitioned.
  • ML that reaches production. Airflow and PySpark workflows feeding high-volume training jobs, with CI/CD so a model change ships like any other code.
  • Finance and ERP data. Financial systems migrations, including ETL between SAP and Snowflake, run across onshore and offshore teams.
