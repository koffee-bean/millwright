# Millwright Data

Source for **[millwrightdata.com](https://millwrightdata.com)**, the site for Millwright Data, Sid Srivastava's data platform, governance, and AI advisory practice.

![Millwright](og-v2.png)

## How it is built

A home page plus generated inner pages for services, industries, case studies, and writing. There is no package manager and nothing to install. A small Python script, using only the standard library, turns the content files in `_src/content/` into finished HTML.

To change an inner page, edit its file in `_src/content/`, then run:

```sh
python3 _src/build.py
```

and commit the generated output with the source. GitHub Pages serves the committed HTML as is, so the build runs on your machine, not on GitHub. Jekyll skips folders that start with an underscore, so `_src/` is never published.

Every page shares one stylesheet, `assets/site.css`, and one script, `assets/site.js`. The home page is the single source for the shared pieces: the build copies the footer, the flags, and the service icons out of `index.html` into every inner page, so change them there. The home page's twelve client logos are still base64-embedded, and the flags and service icons are inline SVG. The only external requests are the Archivo typeface from Google Fonts and the third-party services listed below.

## Hosting and deployment

GitHub Pages serves the repository root from the `main` branch. `CNAME` points the site at `millwrightdata.com`, and HTTPS is enforced in the repository's Pages settings.

Merging to `main` triggers a Pages build that usually finishes in under a minute. Nothing else needs to run.

## Things worth knowing before editing

**The headline resizes itself.** The rotating phrase in the hero cycles through a list of audiences. A script measures the longest phrase and shrinks the headline until it fits on one line, so adding a longer phrase shrinks the headline on narrow screens rather than causing a sideways scroll.

**The time picker does not read live availability.** It offers weekday business hours converted into the visitor's own time zone, and each slot deep-links into Cal.com with that date and time selected. Cal.com shows true availability once the visitor lands there, so a slot that is already taken simply opens the real calendar for that day.

**The booking overlay degrades gracefully.** Cal.com's embed script opens the calendar over the page. If the script fails to load, the same links open the calendar in a new tab instead.

**Service titles need to stay short.** The four cards under "Work with me" sit in a two-column grid, and a title long enough to wrap to a second line pushes its row out of alignment with the one beside it. Keep each title to one line at desktop width.

**Bump the social image filename when you change it.** Platforms and content delivery networks cache that image by its URL, so overwriting it in place leaves people seeing the old one for a long time. Rename it (og-v2, og-v3 and so on) and update the `og:image` tag in `index.html` and `_src/layout.html` at the same time.

**Say "Millwright Data" in text, "Millwright" only in the logo.** Searching the bare word returns industrial millwrights, so every title, label, and sentence uses the full name. The wordmark artwork and its alt text stay "Millwright". The structured data in the page head uses the same name.

**New pages come from new content files.** Copy an existing file in the same `_src/content/` folder, change the comment block at the top and the body, and run the build. The page, its section index, the home page links, the sitemap, and `llms.txt` all update together.

**Every page can have a photo.** The build looks for `assets/img/<type>-<slug>.webp`, for example `service-build.webp` or `industry-games.webp`. If the file exists, it appears as the thumbnail on that page's cards and in the article list. If not, the page renders without one. To add or replace a photo, put the original in `_src/photos/` with that name as a `.jpg`, add a row to `credits.csv`, add a one-line description to `PHOTO_ALT` in `_src/build.py` (the build stops without one, since screen readers read it aloud), and run `python3 _src/photos.py`, then `python3 _src/build.py`. The photo script gives every image the same cream-and-navy tint so new ones match the set.

**Search engines hear about changes automatically.** After every push to `main`, a GitHub Action waits for Pages to deploy, then sends the changed pages to IndexNow, which Bing, Yandex, and other engines share. Pages whose only change is the stylesheet version tag are skipped. To resubmit every page, open the Actions tab, pick IndexNow, choose "Run workflow", and tick "all". The same form can send straight to Bing instead of the shared IndexNow endpoint. Google does not use IndexNow. It reads `sitemap.xml` through Search Console.

**Articles answer first.** Each article's title is a question a buyer would type, and its `answer` field holds a direct answer in two sentences, shown in a box at the top. The detail follows.

**Case study figures must be ones you can defend.** Every number on a case study page should trace to work you can walk someone through on a call.

**Icons come from one master.** They were generated by trimming the supplied artwork down to the mark, then rendering every size from a single transparent copy, so the light and dark versions line up exactly. If the mark changes, regenerate all of them together rather than editing individual files.

## Previewing locally

Serve the folder rather than opening the file directly, because the icon and manifest paths are root-relative and will not resolve over `file://`:

```sh
python3 -m http.server 8000
```

Then open `http://localhost:8000`.
